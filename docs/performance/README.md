# 性能验证 · 0.1.1 · 2026-10-25

本机 Apple M5、32 GiB、macOS arm64。两个基准顺序执行，避免互相争抢 CPU。以下是短时可复现基准，**不是日常 IDE 整进程、GPU 或能耗测量**。CPU 的 100% 表示占满一个核心。

## VS Code 渲染器

在 Chrome 155 的独立无界面进程中，向 Monaco 形状的 DOM 测试页面加载完整生产 `dist/renderer.js`。编辑器 1200×700 CSS px、DPR 2；以约 60 次/秒切换光标目标，测量每组 3 秒、重复 3 次，交替开关顺序。页面不模拟原生光标闪烁。

CDP `Performance.TaskDuration / elapsed` 表示浏览器主线程任务占用等效值；不是操作系统采样的 CPU 时间，也不含 GPU、其他浏览器线程或 VS Code 的扩展宿主、语言服务。比较同一重复轮次的开关差值，再取中位数。

| 场景 | 关闭时主线程占用 | 开启时主线程占用 | 配对增量（百分点） | rAF P95 |
|---|---:|---:|---:|---:|
| 静止 | 1.06% | 1.27% | +0.21 | 16.7 ms |
| 单光标移动 | 3.53% | 5.73% | +2.20 | 16.7 ms |
| 20 光标移动 | 4.70% | 8.11% | +3.52 | 16.7 ms |
| 单光标 + railgun | 3.35% | 5.74% | +2.48 | 16.8 ms |

本次移动场景约每秒 60 个动画帧，静止场景 0 个动画帧；24 个测量窗口均校验了启用状态、Canvas 数量/尺寸和应有的动画帧数。空闲 +0.21 个百分点处于短窗波动量级，不足以归因于插件；各场景结果受 JIT、GC 和调度影响，不应外推为线性缩放规律。

60 次注入/释放的 GC 后 JS 堆为 1,404,760 / 1,394,252 / 1,394,252 字节，节点数均为 28、文档数均为 1，释放后无 Canvas；本轮未观察到持续增长。

Canvas 单个 RGBA 像素缓冲估算为 **12.82 MiB**（2400×1400×4 字节），不含合成器副本、驱动开销。这个缓冲在附着的编辑器中保留，停下只停止动画，不释放画布；分屏会增加画布数量。JS 堆差值远小于画布，不可据此声称插件只占几 KB。

停止移动后验证动画帧计数不再增长、原生光标恢复。另做 60 次注入/释放，每 20 次强制 GC 记录堆和 DOM；这只能检查短时重复释放行为，不能证明所有场景均无内存泄漏。rAF 间隔只能反映页面调度，不能代替实际屏幕呈现帧率。

## IDEA

SDK 为本机 IDEA 2026.2.3 / IU-262.10968.63，JBR 25.0.4。独立图形配置停在许可证初始化，因此**没有取得完整 IDEA 窗口的 CPU、RSS、GPU 或帧率数据**。

替代测量运行在实际 IDEA 的无界面测试入口中：

- 生产 `Motion` 和 `CursorPainter` 向 2× 的 Java2D 离屏图像绘图，每帧清除整张图像。先预热 1000 帧，每组测 1500 帧、重复 3 次。60/120 FPS 是模拟时间步长，循环没有按真实刷新率限速。
- 当前线程 CPU 时间除以帧数，再乘目标 FPS，推算持续绘制的单核占用。此数值**排除编辑器重绘、glass-pane 合成、窗口服务器和 GPU**，不能与上述浏览器数字直接比较。
- 真实无界面编辑器空闲 3 秒，动画计时器触发 **0 次**。创建/释放 60 个编辑器，每 20 次检查服务的编辑器会话数为 **0**。

| 光标数 | 模拟 FPS | 每帧耗时中位数 | P95 耗时中位数 | 绘图线程推算单核占用 |
|---|---:|---:|---:|---:|
| 1 | 60 | 0.240 ms | 0.258 ms | 1.44% |
| 1 | 120 | 0.240 ms | 0.257 ms | 2.88% |
| 20 | 60 | 1.757 ms | 1.848 ms | 10.53% |
| 20 | 120 | 1.785 ms | 1.875 ms | 21.40% |

单光标每帧分配约 0.95–1.00 KB Java 对象，20 光标约 18.9–19.8 KB；这是分配速率，不是存活内存。离屏图像的 12.82 MiB 由测试工具创建，**不是 IDEA 插件的常驻缓冲**。编辑器释放批次后整个 IDE 的 GC 后堆约 136.3 / 137.8 / 137.9 MiB，包含平台缓存与初始化；没有禁用插件的对应对照，不能作为插件内存增量。

## 结论与后续关注

两个实现均通过静止停帧/停计时器检查。单光标核心成本较低；IDEA 的 20 光标高刷新绘图成本明显上升。VS Code 需要优先关注分屏、Retina 下画布内存；IDEA 需要在可正常启动的独立图形配置中继续验证整编辑器重绘成本。当前数据不支持“整 IDE 零开销”或“所有机器稳定 120 FPS”等结论。本次未凭离屏结果修改生产重绘逻辑。

## 复现与原始数据

从仓库根目录运行浏览器基准：

```sh
npm run build
CHROMIUM_PATH="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" npm run benchmark
```

从 `jetbrains-neovide-cursor` 目录运行 IDEA 基准：

```sh
python3 scripts/build.py --test
python3 scripts/smoke.py --performance
# 可选图形测量，需要独立配置正常完成许可证初始化：
python3 scripts/smoke.py --performance --gui
```

运行时需要本地浏览器/IDE 的进程与 socket 权限。两个基准都使用临时配置，不载入日常项目。

原始数据：[浏览器](renderer.json)、[IDEA](idea.json)。浏览器每次运行覆盖前者；IDEA 运行输出在 `jetbrains-neovide-cursor/build/idea-performance.json`，本报告保存了本次副本及环境信息。
